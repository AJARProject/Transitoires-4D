# Transitoires multilingue (XLIFF) / multilingual (XLIFF)

[Français](#français) · [English](#english)

## Français

Transitoires affiche son interface en **anglais, français, allemand et italien**.

### Choix de la langue (menu Langue)
- Le menu **Langue** propose **Automatique (langue du système)**, **Français**, **Deutsch**, **Italiano** et **English**. Chaque langue est écrite dans sa propre langue. Une coche marque le choix actif.
- **Automatique** prend la langue de l'utilisateur du système, `Get database localization(User system localization)`, réduite à sa partie langue (« fr-ch » → « fr »). Si ce n'est ni fr, ni de, ni it, ni en, c'est l'anglais. On n'utilise pas la langue choisie par défaut par 4D, car 4D peut prendre celle de l'application 4D : c'est ce qui faisait démarrer Transitoires en français ([Get database localization](https://developer.4d.com/docs/21-R4/commands/get-database-localization)).
- Le choix est **mémorisé par utilisateur** dans `preferences.json`, dans le dossier des préférences utilisateur de 4D : `Folder(fk user preferences folder)/Transitoires/`, soit sur macOS `~/Library/Application Support/4D/Transitoires/preferences.json` ([Folder](https://developer.4d.com/docs/21-R4/commands/folder)). Il n'est donc ni dans la structure ni dans les données. Si le fichier manque ou est illisible, ou si son contenu ne convient pas, on prend Automatique, sans message d'erreur. Sont concernés : JSON mal formé, `null`, tableau, propriété `language` absente ou qui n'est pas du texte, code inconnu. Le contrôle est fait par `Language_choiceFromText`, testé dans `launch_unitTest`.
- **Au démarrage** : `Language_startup` est la première action de `On Startup`, juste après les déclarations. Elle appelle `SET DATABASE LOCALIZATION` avant tout formulaire et toute barre de menus ([SET DATABASE LOCALIZATION](https://developer.4d.com/docs/21-R4/commands/set-database-localization)).
- **Barre de menus** : `Menu_build` la construit en mémoire (Fichier, Édition, Langue, Mode) avec `Create menu`, et `Menu_install` l'installe dans chaque process. Un menu créé par `Create menu` est partagé : toute modification s'applique tout de suite à tous les process ([Create menu](https://developer.4d.com/docs/21-R4/commands/create-menu)). Au changement de langue, `Menu_applyTexts` réécrit donc les libellés et la coche à leur place, sans redémarrer.
  - Le formulaire Input n'est plus associé à « Barre #1 », qui aurait été ajoutée à droite de la barre ([Associated Menu Bar](https://developer.4d.com/docs/21-R4/FormEditor/properties_Menu)).
  - « Barre #1 » reste dans `menus.json`. Elle ne s'affiche qu'avant `On Startup`.
- **Fenêtres ouvertes** : un formulaire déjà chargé garde sa langue (doc de `SET DATABASE LOCALIZATION`). `Input_reopenAll` demande donc si l'on veut **rouvrir maintenant** la fenêtre Transitoires (via `CALL FORM` puis `CANCEL`) en gardant les filtres, l'année et la recherche. Les modifications non enregistrées sont perdues, et le message le dit. Avec **Plus tard**, la fenêtre sera dans la nouvelle langue à sa prochaine ouverture.
- **Pourquoi pas un redémarrage ?** Les menus et la fenêtre peuvent être rafraîchis de façon documentée : le menu partagé d'une part, la réouverture du formulaire d'autre part. `RESTART 4D` est prévu pour les applications fusionnées et relancerait aussi 4D en mode développement.

### Fichiers
- `Resources/<lang>.lproj/Transitoires.xlf`, avec `en`, `fr`, `de` et `it`. Ce sont des fichiers XLIFF 1.2 ; l'anglais est la langue source.
- Groupes : `menus`, `Input`, `print_form`, `messages`, `values`.
- Clés en camelCase avec le préfixe `tr` : `trInputHeaderInvoice`, `trConfirmDeleteInvoice`…
- Les traductions FR, DE et IT sont une première version (registre suisse). Elles portent `state="needs-review-translation"`, la valeur XLIFF 1.2 que 4DPop XLIFF Pro sait aussi lire. Une fois relue, une cible peut passer à `state="final"`, ou perdre l'attribut.
- `i18n/translations-review.csv` et `.md` : le tableau de relecture (clé, EN, FR, DE, IT, note).

### Dans le code
- Formulaires et menus : la référence `:xliff:clé` ([Menus](https://developer.4d.com/docs/21-R4/Menus/properties), [placeholder](https://developer.4d.com/docs/21-R4/FormObjects/properties_Entry), [titre de fenêtre](https://developer.4d.com/docs/21-R4/FormEditor/properties_FormProperties)).
- Méthodes : `L10n("clé"; valeur1; …)` appelle `Localized string` ([doc](https://developer.4d.com/docs/21-R4/commands/localized-string)) et remplace `{1}`, `{2}`… Si la clé manque, elle renvoie la clé. Elle préserve la variable OK.
- `L10n_count("trMsgX"; n)` choisit `trMsgXOne` ou `trMsgXOther`. Le français met le singulier pour 0 et 1.
- `L10n_value(valeur)` affiche les valeurs stockées : `debit`/`credit` traduits, `Frs` affiché **CHF**. **Les valeurs en base et les requêtes ne changent pas.**
- `filterSummary` construit le texte des filtres actifs, utilisé par le bandeau et le titre d'impression.
- Langue : `Language_startup`, `Language_getChoice`, `Language_saveChoice`, `Language_prefsFile`, `Language_resolve`, `Language_apply`, `Language_isChoice` et `Language_menu` (méthode des éléments du menu Langue). Menus : `Menu_build`, `Menu_addItem`, `Menu_install` et `Menu_applyTexts`. Fenêtres : `Input_reopenAll` et `Input_reopenForLanguage`.
- `AJUI_FloatingLabel_main` traduit un placeholder `:xliff:`, car `OBJECT Get placeholder` renvoie la référence brute ([doc](https://developer.4d.com/docs/21-R4/commands/object-get-placeholder)).
- Formats suisses dans toutes les langues :
  - nombres : formats `|Schweiz` = `###'###'###'##0.00;-###'###'###'##0.00` et `|Schweiz2` = `###'###'##0.0000;-###'###'##0.0000` (`Project/Sources/filters.json`), utilisés par les colonnes, les champs, les totaux et l'impression. Chaque chiffre a besoin d'un caractère `#` ou `0`, sinon 4D affiche `<<<`. Le signe moins prend lui aussi un caractère, d'où une partie séparée pour les négatifs. L'apostrophe est un caractère ordinaire, affiché seulement entre deux chiffres. Le « . » est remplacé par le séparateur décimal du système ([Number format](https://developer.4d.com/docs/21-R4/FormObjects/properties_Display#number-format)). La limite réelle est 99'999'999'999.99, négatifs compris : 4D convertit les réels sur 13 chiffres significatifs ([String](https://developer.4d.com/docs/21-R4/commands/string)). Au-delà, les dernières décimales sont perdues (123'456'789'012.25 s'affiche 123'456'789'012.20), et 999'999'999'999.99 donne `<<<`. `|Schweiz2` accepte au plus 9 chiffres entiers. Affichage : à l'impression (A4 paysage, 80 %, zone imprimable de 1022 px), le tableau s'arrête à 1017 px. Les pieds Montant facturé et Montant payé (130 px, gras) sont garantis jusqu'à -9'999'999'999.99. Ceux des colonnes de montant par année (Column9 et Column10, 100 px) tiennent environ jusqu'à -9'999'999.99. À l'écran Input, les totaux font 150 px ;
  - dates `dd.MM.yyyy` sur les colonnes et les champs de date, et pour la date imprimée ([formats de date](https://developer.4d.com/docs/21-R4/Project/date-time-formats)).

### Ajouter un texte
1. Ajouter la `trans-unit` dans les quatre fichiers, dans le bon groupe.
2. L'utiliser avec `:xliff:clé`, `L10n("clé")`, ou `Menu_addItem(menu; "clé")` pour un élément de menu.
3. Lancer `python3 i18n/check_xliff.py` : il contrôle le XML, le schéma XLIFF 1.2 et les clés dans les quatre langues. La sortie doit finir par `OK`.

### Laissé en anglais (messages de développeur)
- `UT_assert`, `launch_unitTest`, `_days_currentyear`, `_days_nextyear` : tests unitaires.
- `AJUI_FloatingLabel_main` : alerte « You must create the FLabel form object… », qui signale une erreur de construction du formulaire.
- Les messages internes du composant `AJUI_BreadCrumb`, qui n'est pas traité.
- Le titre `window title` de `print_form` : ce formulaire ne sert qu'à imprimer et n'est jamais ouvert en fenêtre.

## English

Transitoires shows its interface in **English, French, German and Italian**.

- **Language menu**: Automatic (system language), Français, Deutsch, Italiano, English, with a check mark on the active choice.
  - Automatic uses `Get database localization(User system localization)` reduced to its language part; anything other than fr, de, it or en falls back to English.
  - The choice is saved per user in `Folder(fk user preferences folder)/Transitoires/preferences.json`, outside the structure and the data.
  - `Language_startup` applies the choice with `SET DATABASE LOCALIZATION` at the very start of `On Startup`.
- **Menu bar**: built in memory by `Menu_build` (`Create menu`) and installed in each process by `Menu_install`.
  - Menus created this way are shared, so `Menu_applyTexts` retranslates them in place for every process.
  - The Input form no longer has an associated menu bar.
- **Open windows**: loaded forms keep their language, so `Input_reopenAll` offers to reopen the Transitoires window now (`CALL FORM` + `CANCEL`), keeping the filters. Unsaved changes are lost, and the message says so. "Later" applies the language the next time the window opens.

- Files: `Resources/<lang>.lproj/Transitoires.xlf` (XLIFF 1.2, English source).
  - Groups: `menus`, `Input`, `print_form`, `messages`, `values`.
  - Keys: camelCase with the `tr` prefix.
  - FR, DE and IT are first translations marked `state="needs-review-translation"`.
- Review table: `i18n/translations-review.csv` / `.md`.
- Forms and menus use `:xliff:key`.
- Methods:
  - `L10n("key"; value1; …)` wraps `Localized string`, replaces `{n}`, falls back to the key and keeps OK;
  - `L10n_count` handles singular and plural;
  - `L10n_value` translates the stored values for display only (`Frs` is shown as CHF);
  - `filterSummary` builds the filter text.
- `AJUI_FloatingLabel_main` resolves `:xliff:` placeholders, because `OBJECT Get placeholder` returns the raw reference.
- Swiss number and date formats are used in every language.
- Amounts: `|Schweiz` = `###'###'###'##0.00;-###'###'###'##0.00`, `|Schweiz2` = `###'###'##0.0000;-###'###'##0.0000` (filters.json), exact up to 99'999'999'999.99 including negatives (4D converts reals on 13 significant digits); `|Schweiz2` takes at most 9 integer digits. Display: on the printout (A4 landscape, 80 %, printable width 1022 px) the table ends at 1017 px. The bold Amount invoiced and Amount paid footers (130 px) are guaranteed up to -9'999'999'999.99; the per-year amount footers (Column9 and Column10, 100 px) hold about -9'999'999.99. Input totals are 150 px wide.
- A malformed preferences.json (bad JSON, null, array, missing or non-text `language`, unknown code) falls back to Automatic without an error (`Language_choiceFromText`, covered by `launch_unitTest`).
- Check: `python3 i18n/check_xliff.py` (well-formed XML, XLIFF 1.2 strict schema, every key used by forms, menus and methods present in the four files).
- Left in English: unit-test and developer messages (`UT_assert`, `launch_unitTest`, `_days_*`, the FLabel template alert), the `AJUI_BreadCrumb` component, and the `print_form` window title (never shown).
